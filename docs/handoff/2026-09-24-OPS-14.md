## Decisions made after ADR-0007 (not in the ADR)

- **503 until OPS-15**: production wires `database/pending.py` (`PendingRepository`), which refuses every call; main.py maps `SliceNotPersistedError` to 503. Routers stay mounted.
- **Role rule** is "never *branch* on a role" in routes/pages; serializing one is fine. AGENTS.md wording and the architecture test changed on the feature branch.
- **Domain-field allowlists** in `tests/architecture/test_conventions.py` gained `user_id`, `instructor_id`, `classroom_id`, `student_id`, `expires_at`, `last_active_at`, `requested_at`, `joined_at`, each with the use case that reads it.
- **Verification mail** goes through a temporary auth port `VerificationMailer` (stub in `integrations/email.py`). When notifications lands, main.py points it at `NotificationService`; nothing else changes.
- **Tabs**: a Member asking for an Instructor tab gets 403; an unknown tab gets 404.
- **Demo mode** lives in `scripts/demo.py`, not a `GREADER_DEMO` switch in main.py, because fakes may not ship in `src/`. Demo card numbers are hard-coded from the prototype until assignments/submissions compute them.
- **Templates**: page templates use only the `_components/` macros for controls (architecture test). Server-rendered open modals (C-02a, C-03a) use `modal(static=true)`.
- **CSS**: Tailwind v4.3.3 standalone binary, not in the repo; README "Styles" has build/watch commands. Root font size stays 16px, body text 13px.
- `GET /classrooms/{id}/summary` lives in the assignments slice (it computes it); the CSV export waits for submissions.
- **2026-09-24 answers:** assignments and generation use the ADR shape on fakes and wire `PendingRepository` in production until OPS-15; the old SQL adapters stay unwired (the assignment adapter maps `is_hidden` to `kind` so its CI tests keep running). Submission-derived numbers come through a `PostingStats` port (seeded in demo). T-03's document list comes through a `DocumentCatalog` port (fake in demo, pending in prod).
- Generation's daily Quota is a constant 20 until A-01; `ClassroomRole` lives in `classrooms/models.py`; `AssignmentContent` in `assignments/models.py`.

- **Submissions (2026-09-24):** score = max score × passed ÷ total, rounded down. Students see edge tests as "Hidden n"; the note only with "show hidden test names". Hidden tests never show output or stderr to Students (page or API); a sample test's traceback shows on S-02d. Every Submission stores `classroom_id`, `assignment_id` and `version_number`; `SubmissionPostingStats` marks Resubmit needed from the version number. State order for S-01 badges: Resubmit needed > Late > Passed > Partial. Run and Submit on a Closed Posting are refused (409 on the page with S-02f). A Member asking `?tab=versions` gets 403, anything unknown 404.
- **CodeRunner:** production wires `integrations/judge0.StubCodeRunner` (every run is a runtime error "not configured"); the demo wires `tests/fakes/submissions.LocalUnsafeRunner`: local Python, no sandbox, 127.0.0.1 only; timeout, CPU/memory rlimits (RLIMIT_AS is ignored on macOS), temp-dir cwd, stripped env; opt-in: its constructor needs `ALLOW_UNSAFE_RUNNER=1` and always refuses `ENV=production`, so an unset ENV fails closed. `DemoSeed` defaults to `StubCodeRunner`; `scripts/demo.py main()` swaps in `LocalUnsafeRunner` only with the flag (AGENTS.md Commands). `ENV` is read from `os.environ` because `Settings` has no field; moving it into `config.py` is a follow-up ticket. ADR-0007 "Open questions" 1 asks what runs code in production. Tests use `ScriptedCodeRunner`.
- **New use cases outside the slice:** `AssignmentService.current_version(actor, classroom_id, assignment_id)` (any role in the Classroom; S-02e reads the reason) and `ClassroomService.is_archived(actor, classroom_id)` (owner or Member; submissions refuse Archived Classrooms with `ClassroomArchivedError`, 409).
- **Allowlist entries** added in `tests/architecture/test_conventions.py`, each with its comment: `submitted_at` (is_late compares it with the deadline; S-02g/T-02 "Submitted"), `posting_id` (Submissions are listed by it for history, T-02 and PostingStats).
- **Rounding (2026-09-24 review):** averages round half up to one decimal in Decimal (`core/rounding.average`), used by S-01/T-01 (via AssignmentService and SubmissionPostingStats) and T-02. Per-Submission scores still floor; ADR-0007 open question 2 asks floor vs half up. Percentages on T-01 Summary still use Jinja `round` (half to even); not changed.
- **Labels:** T-01 "Fail rate" now says its denominator (students who submitted, not everyone enrolled); T-02 "Failing" says counted submissions. S-01 shows no fail rate.
- **Static CSS**: `static/` is outside the OPS-14 scope and there is no Tailwind binary locally, so G-00/S-02/T-02 use only classes already compiled into `app.css` (checked with a script).
