# 5. API ที่ต้องทำ

## Assignment

### GET `/assignments`

ใช้สำหรับแสดง Assignment ทั้งหมด

ต้องทำ:

```text
GET /assignments
```

ผลลัพธ์:

- มีข้อมูล → return list
- ไม่มีข้อมูล → return `[]`

---

### GET `/assignments/{id}`

ใช้สำหรับดู Assignment รายตัว

ต้องทำ:

```text
GET /assignments/{id}
```

ผลลัพธ์:

- เจอ → return assignment
- ไม่เจอ → `404`

ควร return Test Case ของ Assignment นั้นด้วยถ้า schema ที่ Tech Lead เตรียมไว้รองรับ

---

### POST `/assignments`

ใช้สำหรับสร้าง Assignment

```text
POST /assignments
```

ข้อมูลหลัก:

```text
title
problem_statement
difficulty
metadata
```

Validation:

```text
title ห้ามว่าง

problem_statement ห้ามว่าง

difficulty ต้องเป็น
- easy
- medium
- hard
```

---

### PUT `/assignments/{id}`

ใช้สำหรับแก้ Assignment

```text
PUT /assignments/{id}
```

แก้ได้:

```text
title
problem_statement
difficulty
metadata
```

ผลลัพธ์:

```text
เจอ → update

ไม่เจอ → 404
```

---

### DELETE `/assignments/{id}`

ใช้สำหรับลบ Assignment

```text
DELETE /assignments/{id}
```

ผลลัพธ์:

```text
เจอ → delete

ไม่เจอ → 404
```

เรื่อง Test Case ที่เกี่ยวข้องหรือ Cascade

**ไม่ต้องจัดการเอง**

ให้ใช้ behavior ที่ Tech Lead เตรียมไว้

---

# 13. Git Rule

ห้าม push เข้า `main`

ใช้ branch เช่น:

```text
feature/backend-assignment-crud

feature/backend-test-case-crud
```

ไม่จำเป็นต้องแตก branch ย่อยเยอะเกินไป

แนะนำ:

```text
1 branch = Assignment CRUD

1 branch = Test Case CRUD
```

ก่อนเปิด PR:

```text
1. run test

2. run formatter

3. git status

4. git diff

5. เช็คว่าไม่มีไฟล์นอก scope

6. เปิด PR
```

# 14. กฎตอนใช้ AI

ใช้ AI ช่วยเขียนได้

แต่ให้ AI อ่านไฟล์นี้ก่อน

Prompt:

```text
Read backend-teammate-plan.md first.

Your task is CRUD only.

Do not modify database models, migrations, database configuration,
authentication, middleware, Docker, CI/CD, AI service, RAG,
generation service, or shared architecture.

Use the existing project structure and existing CRUD pattern.

Before editing:
1. Tell me which task you are implementing.
2. List files you plan to modify.

After editing:
1. List every modified file.
2. Explain what changed.
3. Show how to test it.

Do not modify files outside the Assignment/Test Case CRUD scope.
```

ห้ามใช้ prompt เช่น:

```text
finish backend
```

```text
complete the backend
```

```text
fix everything
```

```text
implement all missing features
```

เพราะ AI อาจแก้ไฟล์นอก Scope
